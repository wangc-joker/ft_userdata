# DualTrend 持仓管理增强计划

> **历史状态：** 本文是 2026-07-06 的研究计划，其中的“当前主候选”已经过时。最新状态见仓库根目录的 [`CURRENT_DUALTREND.md`](../../CURRENT_DUALTREND.md)，当前研究主候选是 `DualTrendPyramidSecondAdd20V1Strategy`。

## 1. 背景

当前主候选策略：

- `DualTrendRawBreakevenGuardStrongRunnerStructureStrategy`
- 文件：`D:/test/ft_userdata/user_data/strategies/DualTrendMainStrategies.py`

当前策略的强项已经比较明确：

- 入场筛选比早期版本更干净
- `short_pullback_restart` / `short_compression_breakdown` / `long_1d_center_compression` 三条主线已经有稳定盈利基础
- 保本保护、`reach5` 强单放行、compression flush guard 都已经有过完整回测验证

当前比较薄的部分也很明确：

- 止损层次不够细
- 减仓只在少数分支上有较简单实现
- 加仓还没有形成成熟、保守、可验证的框架

因此，下一阶段不优先继续改入场，而是把“持仓生命周期管理”做厚。

## 2. 总体原则

### 2.1 优先级

开发顺序建议固定为：

1. 止损增强
2. 减仓增强
3. 加仓增强

原因：

- 止损决定坏单怎么少亏
- 减仓决定好单怎么少吐
- 加仓才是在已有稳定性的基础上提高收益上限

如果先做加仓，很容易把当前已经稳定的收益曲线放大成更高波动版本。

### 2.2 研究纪律

每一轮只研究一个主题，不混合调参：

- 止损轮：不改减仓 / 不改加仓
- 减仓轮：不改止损 / 不改加仓
- 加仓轮：只在前两轮确定有效后再做

每轮都必须固定：

- pair pool
- max_open_trades
- leverage
- 入场逻辑
- 主策略类

否则结果不可解释。

### 2.3 风险原则

默认只允许：

- 亏损不加仓
- 不做 DCA
- 只允许“盈利后加仓”
- 加仓后总风险不能超过原始风险预算上限

## 3. 止损增强

### 3.1 目标

止损增强不是单纯把固定止损放宽或收紧，而是把“错单识别”从单一价格层，扩展为三层：

1. 入场失败止损
2. 结构移动止损
3. 时间止损

### 3.2 入场失败止损

核心问题：

- 当前有些单不是因为原始结构止损设置错了
- 而是因为入场逻辑在开仓后很快失效，但策略还在继续给它时间

建议研究条件：

#### short 方向

- 开仓后 `3h` 内未出现继续向下扩展
- 开仓后 `6h` 内价格重新收回 `compression_low` / breakdown 区间内部
- 1H 市场重心上移
- 重新站回 `EMA20`
- BTC 4H 不再支持做空
- pair 4H 下跌趋势失效

可能的退出理由：

- `early_fail_short_reclaim_range`
- `early_fail_short_center_up`
- `early_fail_short_btc_flip`

#### long 方向

- 开仓后 `3h-6h` 内未继续向上
- 跌回 breakout / center 区间内部
- 1H 市场重心下移
- 收回 `EMA20` 下方
- BTC / pair 4H 趋势不再支持做多

### 3.3 结构移动止损

核心问题：

- 当前止损保护更多还是价格百分比逻辑
- 还没有充分利用 1H / 4H 结构变化去动态收紧

建议研究逻辑：

#### short

- 盈利超过 `1R` 后，止损抬到最近 1H 小反抽高点上方
- 盈利超过 `2R` 后，止损跟随 1H 市场重心或 `EMA20`
- 若出现横盘压缩后未继续向下，止损进一步收紧

#### long

- 盈利超过 `1R` 后，止损移到最近 1H 回踩低点下方
- 盈利超过 `2R` 后，止损跟随 1H 市场重心或 `EMA20`
- 若出现高位平台但无法继续创新高，止损上移

### 3.4 时间止损

核心问题：

- 有些单既不快速止损，也不顺利扩展
- 它们占用仓位和资金，但并不产生足够收益

建议研究规则：

- 开仓 `24h` 后仍未达到 `+0.5R`，退出或减仓
- 开仓 `48h` 后利润小于 `1%`，退出
- 开仓 `72h` 后趋势环境不再支持当前方向，退出

重点不是机械设天数，而是判断“这笔单是否已经失去时效性”。

## 4. 减仓增强

### 4.1 目标

减仓增强的核心不是“赚到固定点位就卖”，而是：

> 当利润已经足够，但走势不再证明它值得满仓继续持有时，先拿回一部分筹码。

### 4.2 分 tag 设计

#### `short_pullback_restart`

这是趋势延续主线，减仓应偏慢。

建议：

- 到达 `+5%` 后，若结构仍强，不减
- 若 1H 市场重心上移、反抽站回 `EMA20`、下跌动能减弱，再减 `30%-50%`
- 到达 `+10%` 后，不强制全平，保留 runner

#### `short_compression_breakdown`

这是更容易出现假跌破的分支，减仓应偏快。

建议：

- `+3% ~ +5%` 后，如果没有继续放量下跌，先减一部分
- 跌破后若重新收回压缩区间，减仓或直接退出
- 若 BTC 不支持做空，提前收紧

#### `long_1d_center_compression`

这是更偏结构波段的分支，减仓应参考 1D/4H 结构。

建议：

- 1D 中心不再上移，减仓
- 4H 趋势转弱，减仓
- 长时间不创新高，减仓

### 4.3 研究重点

减仓实验要优先比较：

- 固定盈利阈值减仓
- 盈利阈值 + 结构变弱减仓
- 是否保留 runner
- 不同 tag 是否需要不同减仓节奏

## 5. 加仓增强

### 5.1 目标

加仓不是为了摊薄成本，而是为了：

> 在方向已经被验证、风险已经下降后，扩大战果。

### 5.2 边界

只允许：

- 盈利后加仓
- 每笔交易最多加仓 1 次
- 只先研究 `short_pullback_restart`
- 不允许亏损加仓
- 不允许网格式 / DCA 式加仓

### 5.3 建议触发条件

以 short 为例：

- 第一笔仓位已经盈利，如 `+3%` 或 `+1R`
- 止损已经移动到保本或盈利保护位
- 价格反抽到 `EMA20` / 小结构边界失败
- 1H 重心继续下移
- BTC 4H / pair 4H 仍支持空头
- 再次跌破小区间

### 5.4 仓位规则

建议初版只做：

- 加仓比例 `30%-50%`
- 每笔最多加 1 次
- 加仓后账户总风险仍不超过原始单笔预算上限

这意味着加仓前必须先重新计算：

- 新平均持仓价
- 新统一止损位
- 总风险占用

如果做不到这一点，宁可不加。

## 6. 建议实验顺序

### Phase 1：止损增强

目标：

- 降低假跌破 / 假突破亏损
- 降低慢性亏损
- 缩短无效持仓时间

测试项：

- `early_fail_exit`
- `time_decay_exit`
- `structure_trailing_stop`

### Phase 2：减仓增强

目标：

- 减少盈利单回吐
- 保留更高质量 runner

测试项：

- `tag-specific partial exit`
- `weakening-structure partial exit`
- `runner preserve`

### Phase 3：盈利加仓

目标：

- 在不明显放大回撤的前提下提高收益上限

测试项：

- 仅 `short_pullback_restart`
- 仅一次加仓
- 严格总风险上限

### Phase 4：组合验证

只把每个阶段最优规则组合起来，再做完整验证：

- 三年
- 近一年
- 压力期
- 强势期
- tag 拆解
- pair 拆解
- 同交易对比

## 7. 回测输出要求

每一轮都建议固定输出：

- 总收益
- PF
- MaxDD
- Winrate
- Trades
- 平均持仓时长
- 按 entry_tag
- 按 pair
- 按 exit_reason
- 压力期结果

若涉及新退出逻辑，必须额外输出：

- 新 exit_reason 的触发次数
- 触发后带来的净收益
- 被误杀的盈利单数量

## 8. 当前建议

当前最值得优先做的不是加仓，而是：

1. 先做“入场失败止损”
2. 再做“结构变弱减仓”
3. 最后再做“盈利加仓”

如果只能选一个主题先推进，建议先做：

- `short_pullback_restart` 的 `early_fail_exit`
- `short_compression_breakdown` 的假跌破快速退出

因为这两类更可能直接改善：

- 假信号亏损
- 仓位占用效率
- 压力期表现
